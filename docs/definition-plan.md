# Go 跳转定义开发计划

目标是在 Rust 中实现 GoLand 式的名称绑定、类型与成员解析、索引和增量更新，为 Zed 提供可核对的 `textDocument/definition`。Go 工具链提供工作区与构建元数据，Rust 负责声明和引用的语义解析。

## 起点与证据

- 原型支持 `包名.导出符号`，已有 UTF-16 文档同步、未保存缓冲区和增量解析。
- `localchat/server/internal/api/api.go` 的 21 个代表请求中有 7 个命中，14 个缺口分别是导入路径 1 个、局部绑定 1 个、同包声明 6 个、字段 2 个和方法 4 个。
- 对该文件磁盘版本的逐标识符测试中，778 个由 gopls 解析到其他声明的引用位置有 101 个与原型目标文件和起点一致，677 个无结果。这是单文件的位置覆盖率。
- GoLand 的 `GoReference` 和 `GoTypeReference` 依次处理局部块、类型参数、文件和包的作用域，结合导入与类型解析。Go 插件为私有符号、类型、方法等维护索引，并使用引用解析缓存。GoLand 发行包提供实现结构，桌面 IDE 的行为用于核对有差异的个案。

## 阶段

1. **名称绑定与包索引**  
   定位形参、接收者、局部声明、同包声明和导入路径。保留同名遮蔽、短声明时序、未保存修改、原有跨包查询的正确性。重点用例为 `execPath`、`corsMiddleware`、`Context`、`WriteError` 和 `GetMuxVars`。目标是覆盖原先 21 个位置中的 15 个。

2. **接收者与直接成员**  
   以包身份与类型声明定位结构体字段和方法。从显式类型、复合字面量和短声明求接收者类型，并逐段处理字段选择。覆盖 `api.Routes.APIRoot`、`router.Use`、`api.initUser` 和 `api.app.GetSession`。目标是通过原先 21 个位置。

3. **调用链与类型规则**  
   从函数和方法签名解析结果类型，支持多返回值、链式调用、接口声明、嵌入提升、指针方法集、别名与泛型。检查隐藏和歧义时的选择。重点用例为 `router.PathPrefix(...).Subrouter()`、`conn.Send` 和 `c.App.Config().Update.DesktopVersion`。

4. **工作区与增量维护**  
   周期内更新受影响的文件与包，覆盖新增、删除、重命名、模块和构建配置的变化。将 `go.work`、测试包变体与普通包纳入同一包身份模型。保留 Go Modules 与传统 GOPATH 工作区。

## 验证与提交

- 每阶段用独立本地提交记录代码和回归用例。用声明 URI、起点和可知的标识符范围验收，包含遮蔽、未保存编辑及回滚。对照与 GoLand 行为有差异的查询时，以 Go 规范和确认过的 IDE 行为记录预期。
- 每阶段先运行受影响包的 `cargo check`，然后运行对应测试。Rust 原型和 Zed 扩展使用同一个 Cargo 工作区及配置的产物目录。
- 性能对照使用同一 Go SDK、工作区、缓存条件和语义请求。记录冷暖启动到首次正确跳转、编辑后 P50/P95 和峰值内存。主路径 P95 下降 20% 是拟定目标，其余主要场景要求无可重复的性能回退。用 `localchat/server` 和至少一个更大 Go 项目做结论验证。
