# Go 定义跳转第二阶段开发计划

这一阶段完善 `textDocument/definition` 的类型推断，并缩短工作区发生结构变化后的跳转等待。沿用语法树、声明索引和按需解析的架构。Go 工具链加载磁盘上的构建元数据，Rust 解析编辑器缓冲区中的引用。[第一阶段计划与实测记录](definition-plan.md)

## 验收起点

- 基线为 `675640b`。现有套件复测通过 34 个合成位置、`localchat/server` 的 13 个精确位置，以及文件变更、`go.work`、测试包和 GOPATH 四组工作区用例。此前单独扫描 `internal/api/api.go`，778 个由 gopls 定位到其他声明的标识符与 rs-gopls 的目标文件和起点一致。
- 在临时 Go 模块中新增 12 个精确范围探针。rs-gopls 通过类型断言后的字段跳转，另外 11 个均返回空结果。gopls v0.24.0 通过全部 12 个。11 个缺口分别是索引与容器绑定 5 个、匿名结构成员 2 个、函数值 1 个、泛型调用和约束方法 3 个。这个结果用于确定实现顺序。
- `src/semantic.rs` 当前主要从命名类型和已索引的函数结果推断成员。包图失效后，依赖包图的定义请求会同步等待 `go list`。继续扩展语义前先固定正确性和延迟基线。

## 里程碑与本地提交

### 1. 固定回归语料与性能基线

- 把 12 个探针固化到现有 stdio 测试。每个用例保存查询位置及预期目标文件和 UTF-16 标识符范围。分别统计目标缺失、目标错误、预期空结果和请求错误，保留 gopls 返回的完整候选。记录基线缺口，阶段末全部转为通过条件。
- 固定真实项目修订、Go SDK 和构建参数。以 `localchat/server` 的 `532228d` 为首个对照修订，保留 `internal/api/api.go` 的逐位置检查，从 `internal/api`、`internal/app`、`internal/store` 按局部、包级、成员和测试用例补充位置，并在 Go SDK 的 `GOROOT/src` 中选取 `net/http` 及其测试包验证跨文件、跨包与构建变体。真实仓库只读，未保存编辑通过 LSP 发送。
- 扩展现有对照脚本，运行时输入候选、上阶段基线和 gopls 三个可执行文件路径。每次保留版本、场景、预期位置、实际位置、耗时和失败信息，导出可比较的结果。

### 2. 容器类型、匿名结构与局部绑定

- 局部扩展类型表示，按需解析数组、切片、map、channel、匿名结构和匿名接口。区分命名类型的底层类型与自身方法集。匿名或局部声明以其来源范围和作用域区分，避免同名结构跳错目标。
- 补齐切片和数组下标、map 查询及逗号 ok、通道接收、常见 `range` 和 `select` 绑定。复用现有字段查找，覆盖 `items[i].Field`、`for _, v := range items` 和 `case v, ok := <-ch`。同一组验证 map 元素和切片元素的可寻址性差异，以及无效指针接收者调用的空结果。[Go 规范的索引表达式](https://go.dev/ref/spec#Index_expressions) · [选择器](https://go.dev/ref/spec#Selectors) · [接收操作](https://go.dev/ref/spec#Receive_operator)
- 验收 7 个相关缺口，另加命名容器、`type New Base` 的字段和方法集、`[]T{{Field: v}}` 的省略类型字面量，以及 map 键表达式的普通名称绑定。[Go 规范的类型定义](https://go.dev/ref/spec#Type_definitions)

### 3. 函数值与方法值

- 保留可调用值的参数和结果签名。支持函数字面量、局部函数变量、命名函数类型、函数类型的字段，以及从 `v.Method` 或 `T.Method` 得到的可调用值。沿用多返回值索引，并覆盖跨文件包变量 `var value, err = makeValue()` 的结果类型。
- 验收 `factory().Field`、`makeFactory()().Field` 和 `value, err := callback()` 中由调用结果驱动的成员跳转。覆盖局部遮蔽和闭包，确认对函数变量本身执行跳转仍定位到它的绑定。[Go 规范的方法表达式](https://go.dev/ref/spec#Method_expressions) · [方法值](https://go.dev/ref/spec#Method_values)

### 4. 泛型函数实例化与约束方法

- 从已解析的签名、普通实参和显式类型实参建立替换，支持常见的全部显式、部分显式和隐式类型推断。优先打通 `Identity(Record{}).Field`、`Identity[Record](Record{}).Field`、约束上声明的方法，以及 `S ~[]E` 这类基础底层类型约束。
- 验收跨包泛型工厂、显式和隐式调用、多结果、方法约束、同名类型参数。对冲突推断、未完成的实参和无法唯一确定的成员，保留空结果；验证第一阶段的命名泛型类型、别名与接收者替换。[Go 规范的类型推断](https://go.dev/ref/spec#Type_inference)

### 5. 包图刷新与编辑响应

- 区分只影响声明索引的修改和需要重新加载构建元数据的修改。合并连续的文件事件，避免为每个事件重跑全工作区 `go list`。包图加载放到后台，按变更版本提交结果；仅发布当前变更版本的加载结果。
- 包图刷新期间，保持局部查询和确定仍有效的包可用。需要新包图的查询使用已确认的包身份；文件删除、包名或构建标签变化时及时撤除过期目标。打开的缓冲区继续优先。覆盖未保存的导入切换，以及当前已知活动包中尚未保存的新 Go 文件。
- 在 stdio 测试中确认客户端协商并应答动态监听注册。用可控延迟复现事件连发、加载中再修改和失败后重试，统计批量变更及首次打开测试文件所触发的 `go list` 次数。保留 Modules、`go.work`、GOPATH、内部与外部测试包回归。

### 6. Zed 验收和实测记录

- 复用 Windows 隔离测试配置和已配置的 Cargo 产物目录。本地发布构建用 `tools/test_zed.ps1 -PrepareOnly` 装载。打开 `localchat/server`，从 Go 源文件的 Language Servers 状态核对 `rs-gopls`，用启动日志或进程路径和发布文件的哈希核对实际加载版本，复测 `corsMiddleware`、`initUser`、`GetSession`。再用阶段测试项目复测容器、函数值、泛型，以及未保存移动目标、关闭目标缓冲区后恢复磁盘位置的跳转。
- 对有真实差异的稳定用例，在同一工具链下手动核对 GoLand 的 **Go to Declaration**，记录 IDE 版本、查询位置和观察到的目标。按 Go 规范判断语义和歧义，gopls 作为自动差分基线。将编辑器行为、语义差异和性能结果分别记录。[GoLand 源码导航说明](https://www.jetbrains.com/help/go/navigating-through-the-source-code.html#navigate-between-code-elements)

## 阶段完成标准

- 原有 47 个精确位置和四组工作区用例继续通过，新增 12 个探针全部通过。真实项目的固定样本逐位置核对，任何错误目标或既有命中退化均需修复。每一步先运行 `cargo check -p <受影响包> --locked`，再跑对应测试，分别提交本地 Git。
- 同机、同 Go SDK、同源文件版本，按场景对照基线与候选，轮换服务器运行顺序。每个场景至少 5 次独立会话，主要暖态路径每场至少 80 次 LSP 范围编辑。按无语义编辑、修改调用方或依赖签名、构建变更和新文件分别采样，轮换局部、同包及跨包目标。分别报告新进程首次正确跳转、暖态 P50/P95、构建变更后首次正确跳转、主进程及整个进程树的峰值工作集。区分新进程复用 Go 缓存、暖会话与能单独复现的冷缓存，并记录 gopls 的诊断配置。失败请求单列，必须先满足正确性再比较速度。
- 在 `localchat/server` 和 `net/http` 样本中，原有暖态跳转 P95 相对上一阶段基线的回退不超过 10% 或 1 ms 中较大者。对于双方都能正确跳转的主要编辑路径，以 P95 至少比 gopls 低 20% 为目标。包图刷新期间的局部跳转按同一回退上限与本阶段的常规暖态结果比较。首次正确跳转的中位数相对上一阶段基线的回退上限取 10% 和 100 ms 中较大者。结果按工作区和操作分别报告。
- 后续候选包括类型定义、查找引用和实现跳转，以及不受同一 `go.work` 管理的多个 LSP 工作区文件夹。先完成本阶段的定义跳转验收。
